Semantica **exit code invariata** (0 anche con finding WARN/BAD; ≠0 solo per errori sistemici; `--exit-on-bad` per il gate) — CF-116 non deve cambiarla. **Back-compat**: ogni nuovo campo/flag ha default che preserva il comportamento attuale. Test come sempre: unit in-test (temp file, `httptest`, conteggio concorrenza), mai rete/infra reale; output user-facing in **inglese**. Ogni item è una release a sé.

- [ ] **CF-115 — Config include / `conf.d`**: `include: [path…]` (relativi alla config) e/o merge di una directory `conf.d/`, così una flotta grande si divide per team/servizio in più file uniti in un solo config. Deep-merge documentato (modulo presente in un file incluso si somma/rimpiazza in modo prevedibile), **cycle detection** e errore chiaro sui path illeggibili. Interpolazione `${...}` applicata dopo il merge. Test con temp file (include annidati, ciclo, override).
- [ ] **CF-116 — Cap di concorrenza globale**: `max_concurrency` (config) + `--max-concurrency` (flag) per limitare i check paralleli a livello di run — oggi `engine.RunWith` lancia una goroutine per job **senza tetto**, scomodo con centinaia di target. Default `0` = illimitato (back-compat); il cap si applica sopra i semafori per-modulo esistenti (es. certs 16). Test osservando la concorrenza di picco con un check strumentato.
- [ ] **CF-117 — Composizione di stack**: `--stack a,b,c` applica gli overlay **in ordine** (last-wins), così i profili compongono (base → regione → ambiente) invece del singolo overlay attuale. Retro-compatibile con `--stack singolo`. Il desktop espone gli stack combinabili. Test sull'ordine di overlay e sui default applicati dopo il merge.
- [ ] **CF-118 — Fan-out multi-sink**: emette un singolo run verso **più output insieme** (`--output json,slack` o `outputs:` in config, ciascuno con la sua destinazione/opzioni), riusando i renderer `internal/output` senza rilanciare i check. Errori per-sink isolati (un webhook giù non blocca gli altri). Test con `httptest` multipli + render su file.
- [ ] **CF-119 — Label globali & arricchimento output**: `labels: {env: prod, region: eu}` in config, propagate ai finding e **esposte negli output** (label Prometheus, campo in JSON/OTLP, disponibili nei template webhook) per routing/dashboard. Nessun segreto (solo metadati operativi). **Chiude M29.** Test su render Prometheus/JSON con label.
